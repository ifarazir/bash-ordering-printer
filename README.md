# Bash Printer Agent

چاپ فیش روی پرینتر حرارتی ویندوز. یک فایل `exe` که روی کامپیوتر صندوق اجرا می‌شود، پرینترهای
نصب‌شده را به پنل گزارش می‌دهد و فیش‌هایی را که پنل در صف گذاشته چاپ می‌کند.

سرویس عمداً از پلتفرم مستقل نگه داشته شده تا همین ریپو بدون تغییر در MagnetFood هم استفاده شود؛
هیچ چیز داخلش نام برند را نمی‌داند.

## چرا تصویر چاپ می‌شود و نه متن

پرینترهای حرارتی (از جمله Remo) فارسی و چینش راست‌به‌چپ ندارند. فرستادن متن یعنی خروجی
درهم‌ریخته. به‌جایش پنل، فیش را با فونت و لوگوی خودش به PNG تبدیل می‌کند و این برنامه فقط
تصمیم می‌گیرد آن تصویر با چه اندازه‌ای روی کاغذ بنشیند.

## نصب روی کامپیوتر صندوق

۱. در پنل مدیریت → صندوق فروش → پرینترها، یک دستگاه جدید اضافه کن. **کلید فقط همان یک بار
   نمایش داده می‌شود.**
۲. `BashPrinterAgent.exe` و `appsettings.example.json` را در یک پوشه بگذار.
۳. فایل نمونه را به `appsettings.json` تغییر نام بده و پرش کن:

```json
{
  "apiBaseUrl": "https://api.bash-food.com",
  "agentKey": "کلیدی که پنل نشان داد",
  "printerDpi": 203,
  "pollIntervalMs": 3000
}
```

۴. `BashPrinterAgent.exe` را اجرا کن. پنجره وضعیت اتصال را نشان می‌دهد.
۵. برگرد به پنل: پرینترهای این کامپیوتر آمده‌اند؛ آن که فیش می‌زند را انتخاب کن.

برای اجرای خودکار با روشن شدن ویندوز، یک شورتکات از exe در
`shell:startup` بگذار.

## گزینه‌های خط فرمان

```
BashPrinterAgent.exe --list-printers   نام دقیق پرینترهای نصب‌شده
BashPrinterAgent.exe --version
```

`--list-printers` وقتی به درد می‌خورد که پرینتر در پنل ظاهر نشده و می‌خواهی بدانی ویندوز اصلاً
آن را می‌بیند یا نه.

## ساخت

سه راه، همه یک خروجی می‌دهند: `BashPrinterAgent.exe` — self-contained، بدون نیاز به نصب
runtime روی کامپیوتر مقصد.

**روی ویندوز:**

```powershell
./build.ps1
```

**روی هر سیستم‌عاملی (mac/Linux هم) — cross-compile:**

پروژه فقط به پکیج `System.Drawing.Common` وابسته است و WinForms/WPF ندارد، پس exeی ویندوزی
از روی mac یا Linux هم ساخته می‌شود:

```bash
dotnet publish src/BashPrinterAgent/BashPrinterAgent.csproj -c Release -o dist
```

**روی CI (بدون هیچ ماشین محلی):**

`.gitlab-ci.yml` در همین ریپو هست؛ با یک Linux runner، exe را به‌عنوان artifact می‌سازد.
کافی است در تنظیمات پروژه در hamgit یک runner فعال باشد، بعد از هر push فایل از قسمت
artifacts قابل دانلود است.

## اتصال به API

هیچ پورت ورودی روی کامپیوتر صندوق لازم نیست؛ همه‌چیز خروجی HTTPS است.

| کار | مسیر |
|---|---|
| heartbeat + گزارش پرینترها | `POST /api/v1/print-agent/heartbeat` |
| گرفتن کار بعدی | `GET /api/v1/print-agent/jobs/next` |
| دریافت تصویر یک نسخه | `GET /api/v1/print-agent/jobs/{job}/copies/{n}` |
| اعلام نتیجه | `POST /api/v1/print-agent/jobs/{job}/complete` |

احراز هویت با هدر `X-Print-Agent-Key`. کلید متعلق به دستگاه است نه به یک کاربر، پس رفتن یک
صندوقدار پرینتر را از کار نمی‌اندازد.

همان یک درخواست heartbeat سه کار می‌کند: زنده بودن دستگاه را اعلام می‌کند، لیست پرینترها را
تازه می‌کند، و می‌گوید کدام پرینتر انتخاب شده. چراغ وضعیت در صفحه‌ی صندوق از همین می‌آید.

فاصله‌ی بین نسخه‌ی مشتری و نسخه‌ی آشپزخانه روی خود کار مهر شده، نه در تنظیمات این برنامه —
کاری که در صف است همان‌طور چاپ می‌شود که ثبت شده، حتی اگر بعدش کسی عدد را در پنل عوض کند.

## عیب‌یابی

| نشانه | علت معمول |
|---|---|
| `appsettings.json not found` | فایل نمونه را کپی و تغییر نام نداده‌ای |
| `offline — ...` در پنجره | مشکل شبکه یا `apiBaseUrl` اشتباه |
| `connected — no receipt printer chosen` | در پنل هنوز پرینتر انتخاب نشده |
| `Windows has no printer named "..."` | نام پرینتر در ویندوز عوض شده؛ با `--list-printers` چک کن |
| فیش نصف عرض چاپ می‌شود | `printerDpi` با دستگاه نمی‌خواند (معمولاً ۲۰۳) |
